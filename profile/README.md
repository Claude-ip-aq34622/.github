<p>在机房段上栽过跟头的人，换线路时最容易犯的错是只看价格和地区，不看参数。「真实住宅IP」不是一个形容词，而是一组可以逐项核对的字段：ASN 归属、地址段类型、双 ISP 标记、地区粒度、会话保持时长、并发上限、变更冷却期。这七项里任意一项不达标，用起来就是另一回事。下面按说明书的方式，把每项参数怎么读、建议取什么值、在哪里查，一条条摊开。</p>

<h2>一、参数总表：七项里先锁五项</h2>

<h2>二、地区可指定：到底能指定到哪一级</h2>
<p>「地区可指定」这句话在不同供应商嘴里含义差得很远。有的只是能选国家，有的能选州省，有的能精确到城市甚至邮编区。级别不同，能做的事完全不同。</p>
<h3>三级粒度分别对应什么场景</h3>
<p>国家粒度只够做语言和时区对齐，适合账号资料里只填了国家的场景。州省级粒度可以对齐账号里的账单地址和电话区号，这一层通常已经够用。城市级粒度才是给本地化运营准备的，比如要配合线下门店地址、要做本地搜索结果核验，这时候城市不对就会露馅。采购前直接问一句「城市能不能锁定，锁不住能不能退款」，答案基本能反映真实能力。</p>
<h3>整批同号段的真实含义</h3>
<p>同一个 /24 段里连续分配几十个地址，好处是路由路径一致、延迟接近、运维只维护一条规则；坏处是这一整段在外部看来高度相关。合规的做法是把它当作「同一地区的批量采购」，而不是当作「互相隔离的环境」。真要互相隔离，得靠不同的段、不同的 ASN，甚至不同的接入方式，这一点在签约时就要说清楚，别指望同段地址之间天然不相关。</p>

<h2>三、ASN 与归属：自己动手核一遍</h2>
<p>供应商给的截图都可以做得很好看，唯一可信的是自己查出来的结果。</p>
<h3>三条命令查完基础信息</h3>
<p>第一条，whois 查地址归属，看 netname、org-name、abuse-mailbox 三项是否指向运营商而不是托管商。第二条，查 origin AS，用 whois -h whois.radb.net 加地址，或者用 bgp.he.net 的页面输入地址看 AS 号与上游列表。第三条，traceroute 看最后三跳，家宽线路的最后几跳通常落在运营商接入网，机房线路会落在数据中心交换设备上。三条结果互相印证，比任何一张宣传图都可靠。</p>
<h3>双 ISP 标记怎么判断真假</h3>
<p>真正的双 ISP 指的是这段地址在路由上具备两个可用的上游运营商，任一上游中断时能切换。判断方法看 bgp.he.net 里该前缀的 upstream 数量与 AS path 长度，再看两条路径的延迟差。如果一个「双 ISP」产品查出来只有单上游，那它只是换了个说法的普通住宅段。这个字段值得多花十分钟核，因为它直接决定线路抖动时会不会整批掉线。</p>
<h3>延迟与丢包的基础基线</h3>
<p>用 mtr --report -c 100 打目标地址，重点看三件事：平均延迟、第 3 到第 8 跳的丢包是否延续到末跳、晚高峰时段（当地 20:00 至 23:00）的数据与白天差多少。家宽线路晚高峰抖动是常态，能接受的上限大致是延迟上涨不超过 40%、丢包不超过 2%。超过这个量级，日常对话会开始出现等待感。</p>

<h2>四、会话与并发：决定能不能长期挂着</h2>
<p>很多线路在短测时表现很好，挂上两天开始出问题，原因基本集中在会话保持和并发这两项。</p>
<h3>会话保持时长怎么测</h3>
<p>做法很简单：挑一条线路，写个每五分钟请求一次出口查询接口的脚本，记录返回的 IP 和时间戳，连续跑 48 小时。统计出现过的不同 IP 数量，以及每次变化的间隔分布。如果 24 小时内出现两次以上变化，这条线路不适合长期挂着的账号，只适合短任务。测试期间不要用业务账号，用测试号跑，避免把不稳定因素带到正式环境。</p>
<h3>并发上限要按实测的三分之二用</h3>
<p>标称 200 并发不代表 200 并发时体验不变。实际测法是从 20 并发开始，每轮加 20，记录每轮的成功率与 P95 响应时间。找到成功率开始下滑的拐点，把它乘以 0.66 作为日常上限，留出的余量用来应对突发。这个做法看起来保守，但比事后排查「为什么下午总超时」省事得多。</p>

<h2>五、变更与退出：容易被忽略的三个参数</h2>
<h3>换 IP 的冷却期</h3>
<p>问清楚两件事：一是同一账号换 IP 的最小间隔，二是换 IP 后原地址是否会被回收给别人。前者影响养号节奏，后者影响隔离效果。合理的产品设计会给出按天计的冷却期，并且明确回收策略。如果对方说「随时换、不限次」，通常意味着地址池在高速轮转，这种池子的地址历史往往很杂。</p>
<h3>计费口径与退订规则</h3>
<p>按小时、按天、按月三种口径在团队规模不同时差异很大。二十个号以下按月更省心，五十个号以上按小时配合弹性开关能省下不少。价格区间参考：住宅静态地址大致在每个每月几十元到一百多元，双 ISP 与指定城市会更高，仅供参考。签约前确认未用完的时长能否结转、停用期间是否继续计费，这两条写在合同里比口头说更重要。</p>
<h3>数据清理与交接</h3>
<p>退订时要确认三件事：账号绑定关系是否解除、日志保留多久、地址是否立即释放。团队交接场景下，还需要一份能复现环境的记录，包括每个账号对应哪个地区、哪条线路、最后一次变更时间。这份记录不需要复杂，一张表就够，但缺了它，换人接手时要重新摸一遍。</p>

<h2>常见问答</h2>
<h3>整批同号段会不会更容易被一起识别？</h3>
<p>答：同段地址在外部视角确实高度相关，这是客观事实。它的价值在于路由一致、运维简单，不在于互相隔离。如果业务需要多个互不相关的环境，应该按不同段、不同 ASN 分批采购，而不是指望同段地址之间有天然屏障。</p>
<h3>怎么快速判断一条线路是家宽还是机房？</h3>
<p>答：三步合看。whois 的注册主体是不是运营商、origin AS 是不是家宽 ASN、traceroute 末几跳是否落在接入网。三项都指向家宽才可信，只靠一项容易误判，因为部分机房段会做伪装登记。</p>
<h3>会话保持多久算合格？</h3>
<p>答：长期挂着的账号，24 小时内不漂移是底线，48 小时不漂移比较理想。短任务场景可以放宽，但需要有断线重连和状态恢复的机制，否则一次漂移就可能让正在跑的会话中断。</p>
<h3>价格差一倍，差在哪里？</h3>
<p>答：通常差在地区粒度、双 ISP 备份、地址历史干净度和并发真实上限这四项上。便宜的那批往往在地区粒度和地址历史上妥协，短期看不出问题，跑久了才会暴露。建议先用小批量试，把四项参数都实测一遍再决定放量。</p>
